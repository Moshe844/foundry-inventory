Commercial capacity
Starter $199: 500 active SKUs / 1,000 rows per import.
Growth $499: 25,000 active SKUs / 100,000 rows per import.
Pro $999: 250,000 active SKUs / 1,000,000 rows per import.
Custom/Enterprise: 2,000,000 active SKUs / 5,000,000 rows per import;
agreed contract overrides are supported. These are allowances, not a claim
that every format, source or workload has been certified at those volumes.
Active SKU and product capacity is account-wide; each variant counts. Paid
product add-ons increase both. Existing team, location, usage and capability
limits remain enforced. Deletion excludes an inventory from pooled usage;
restoring or transferring it rechecks capacity. Permanent deletion retains the
capacity counter until canonical products and SKUs have been removed.

Audit disposition
F01: CSV/column overflow and incomplete quoted rows now fail explicitly. Large
CSV reads use compact row offsets; cross-page duplicate checks use scratch disk.
F02: absolute ERP snapshots enforce per-source/position versions or timestamps.
Stale updates are ignored; equal versions with conflicting counts are rejected.
Checkpoint and physical effect commit together under concurrent delivery.
F03: unsupported foreign-currency posting is rejected atomically. This is not
an implementation of arbitrary FX conversion or multi-company consolidation.
F04/F06: serial-to-lot membership and lot balances survive receipt, issue,
transfer, dispatch, arrival and returns. Expired sales/picks are refused;
explicit disposal remains supported. Cross-wave lot/serial reservations count
only active work, and scan IDs cannot be replayed against a different wave.
F05: native fractional, catch-weight and dual-unit stock remain unsupported.
Clover fixed-point units are decoded accurately and unsupported fractions are
retained for review, never rounded or multiplied into stock. Whole-unit balance
overflow beyond the exact integer range rolls back.
F07: indexed exact SKU lookup runs before broad discovery. PostgreSQL trigram
indexes rank typo candidates before bounding results. Search remains a ranked
response, not an exhaustive export of every approximate match.
F08: full native ERP snapshot/delta/freeze/activation cutover remains a gap.
Catalogue/opening-stock import must not be represented as migration of all open
orders, reservations, counterparties and historical financial positions.
F09: connectors remain subject to existing provider availability, credentials,
distribution and live qualification. A generic typed API does not automatically
understand SAP, Dynamics, NetSuite, Odoo or every proprietary ERP.
F10: planning uses sparse evidenced positions, scoped aggregation, visible
continuation and durable SKU cursors, avoiding SKU-by-location multiplication.
Planning and reconciliation batches share oldest-first maintenance scheduling;
an endless stream of higher-priority planning continuations cannot starve older
reconciliation. Other job kinds retain their ordinary priority ordering.
F11: source context and validation read bounded pages. Indexed execution
identities, catalogue preparation, stock application and reconciliation use
bounded reads; execution checkpoints commit with each page and survive crashes.
Catalogue preparation also resumes inside a wide variant family.
The catalogue session lock spans these durable commits, excluding manual product
creation and another direct import in the same inventory until execution exits.
Other inventories remain independent; crashed connections release the lock.
Multipart admission bounds simultaneous buffered uploads. Six catalogue adapters emit
records as pages arrive; Square and BigCommerce join stock/family facts through
scratch indexes. Provider mapping uses 500-record batches; previous values are
stored on scratch disk and catalogue/commerce reconciliation is paged.
Incomplete or conflicting provider snapshots cannot replace the saved catalogue.
Provider snapshot application still uses one transaction; discovery is restarted
after interruption. It is not yet a durable generation-by-generation sync.
CSV source bytes/string still reside in memory. Analysis is a long transaction.
XLSX and other structured formats are not million-row certified; their format
limits remain separate from plan allowances.
XLSX defaults now bound expanded parts to 128 MiB and total expansion to 256 MiB;
larger dedicated deployments can override these explicitly. ZIP directories,
actual decompression bytes, declared lengths and CRCs are checked. Corrupt or
missing worksheets fail the entire source instead of silently dropping data.
Xero Items is not documented among
its paginated endpoints. Provider response bodies are bounded to 32 MiB; a large
unpaginated response fails safely and needs a staged source export.
F12: catalogue name/newest pages use cursors and page-scoped aggregates;
warehouse waves/orders/lines/cartons have bounded pages with whole-wave totals
and complete-shipment packing checks. PO/SO/bill/invoice/payment/shipment numbers
use atomic counters, including imported/manual numbers and rollback safety.
Product lot and serial lists now return 100-record pages with exact lookup,
explicit continuation and complete product totals. Lots retain expiry ordering.
Automatic provider imports keyset-page pending identities and load only selected
product families; matching no longer counts the entire pending catalogue after
each SKU. Owner matching pages 100 source records and bounds searchable target
lists. Exact SKU lookup runs first. Database statement triggers track semantic
catalogue/mapping revisions, preserving stale-approval safety without loading
the whole source; unchanged refreshes and rolled-back changes keep the revision.
Complete provider families remain atomic, so exceptionally large single families
still need dedicated qualification.
Stock-sorted/grouped catalogue views still perform broad database aggregation;
large option-value sets, warehouse container selectors and contention need further
qualification.
F13: imports now preserve up to 32 explicit option axes. Existing current-native
manufacturing/custody/rental services were preserved, but arbitrary regulated
quality release, catch weight, all kit forms and intercompany accounting are not
certified by this release. No capability was enabled solely by changing its label.
F14: million-row end-to-end certification passed on commit 237c6c8 (details below).
A newer run on b05b216 is still running. Later correctness changes have focused
regressions; do not describe a plan allowance as certification of every workload.
