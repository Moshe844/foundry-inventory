## Stripe `stripe_billing / http_request / 2026-09-30.endive`

`stripe-billing.js` calls the Stripe REST API with pinned `Stripe-Version: 2026-09-30.endive`. `provider-http.js` invokes `network.after` after **each HTTP attempt**, including failed attempts and idempotent retries. The event's `http_request` unit counts the attempt; it is not a customer usage debit. Current paths cover Checkout sessions, portal sessions, subscriptions/schedules, invoices/previews, invoice payments, credit notes, invoice items, prices, payment intents/methods, and balance transactions. An unknown future Stripe endpoint remains unpriced and raises a critical warning.

[Stripe Billing pricing](https://stripe.com/billing/pricing) charges on Billing volume (standard pay-as-you-go 0.7%), not these REST attempts. [Stripe Payments pricing](https://stripe.com/pricing) charges on transactions and applicable products; Stripe Tax can have separately priced API calls. Therefore the ordinary Billing/Payments HTTP attempt is classified `VERIFIED_NO_INCREMENTAL_REQUEST_FEE`, with explicit source/date on each cost event and **no synthetic $0 cost rate**. The migration reclassifies existing exact-version attempt events and resolves their stale missing-rate warnings. Actual payment/refund/dispute fees remain reconciled from Stripe balance transactions; Billing volume, Tax and any negotiated fee require separate Stripe statements/fee evidence before profitability certification.
